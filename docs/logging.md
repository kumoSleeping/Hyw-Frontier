# 请求日志与耗时分析

本地调试网页默认写入 `~/.hyw-frontier/logs/`；生产 Entari 默认写入 `/opt/entari/frontier-home/entari/logs/`（由插件 `home` / `log_home` 决定）。每次已接收的问答对应一个 `request_id` 和一份 JSONL 文件，执行期间持续写入，异常或取消也保留已完成的阶段。没有匹配到 `/q` 的消息不会进入问答日志，需要查询 Entari 的平台收消息日志。

## 记录内容

| 范围 | 可分析内容 |
|---|---|
| 整次请求 | 时间、问题、模型、配置、入口、总耗时、成功/失败/取消、错误码 |
| 每轮模型 | 请求时间、首次输出延迟、模型调用耗时、token 用量、最终文本、工具选择 |
| 每个工具 | 名称、调用 ID、参数、实际执行耗时、状态、错误码、结果材料 |
| 搜索与 Reader | 每条查询/网页耗时、结果数、缓存、失败状态 |
| 搜索配图 | 每张图下载/压缩耗时、状态、尺寸、字节数、选用数量 |
| 截图 | 生成、下载、预览压缩、裁剪压缩的独立阶段 |
| 聊天输入 | 消息解析、附件准备、各附件下载与压缩、聊天条数和输入大小 |
| 回答输出 | 绘图耗时和内部步骤；生产另记录 JPEG 编码、过程介绍/文字/图片发送耗时及回执 |

日志不保存图片二进制、Base64、图片缓存、逐 token 增量、模型思考正文或签名。只记录图片的标识、来源、大小和处理状态；URL 去掉查询参数和登录信息，凭据字段移除。问题、最终回答和工具文字材料仍属于私有日志。日志目录权限0700、文件0600。生成的回答图片和本地页面展示资源属于原有输出流程，不会复制进日志。

核心 `answer()` 仍不自动写文件；它通过 `on_event` 交给调用方记录。本地网页与 Entari 已接入相同的日志脱敏规则。

## 计时口径

新日志标记 `log_schema_version=2`，轮次汇总标记 `timing_version=2`。单位均为毫秒，耗时使用单调时钟，时间戳使用 UTC。

- `model_ms` 仅计算模型调用，不包含图片压缩。
- `tool_ms` 为该轮工具批次的实际等待时间，不包含随后自动下载配图的时间。
- `media_download_ms` 与 `image_processing_ms` 分别记录自动配图的下载和处理时间。
- `tool_end.duration_ms` 从工具实际开始执行计算，不含线程池排队；调用总等待可从 `tool_start` / `tool_end` 的时间差看出。
- `stage_start` / `stage_end` 用 `stage_id` 配对，包含阶段名、耗时、状态、所属工具/轮次或附件编号。`stages` 可定位未结束的阶段。
- 并行工具、并行附件及嵌套阶段会重叠，**不能把所有阶段耗时相加当作总耗时**。截图内部步骤包含在对应工具耗时内；附件下载和压缩包含在附件准备阶段内。
- 旧日志未标记第二版计时口径，旧 `model_ms` / `tool_ms` 可能包含压缩/下载时间，不与新数据直接混算。

生产日志保留上限沿用配置：7天、100份、总64 MiB、每请求2 MiB。达到详情限额会记录截断标识并优先保留最终状态、轮次和阶段统计；进程强制退出等未正常收尾的情况可能没有最终摘要。本地每请求上限16 MiB。

## 查询

本地精简查询：

```sh
.venv/bin/python -m hyw_frontier.cli logs --query '关键词' --limit 5 --compact
```

生产服务器上查询：

```sh
/opt/entari/.venv/bin/python -m hyw_frontier.cli --home /opt/entari/frontier-home/entari logs --query '关键词' --limit 5 --compact
```

去掉 `--compact` 可查看搜索、页面和图片处理详情；需要原始事件时按返回的 `file` 查看对应 JSONL。新字段只对更新后的请求生效，不会补造历史耗时。
